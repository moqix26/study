## 0. 先确定项目标准

### 0.1 这不是“把接口跑起来就算完成”

一个能写进简历的项目至少要同时具备：

1. **业务闭环**：创建、详情、列表、更新、禁用、启用、删除、过期、自定义短码和基础跳转（`/r/:code`）都能工作。
2. **正确性**：鉴权、归属校验、唯一约束、并发幂等、数据库迁移和错误语义清楚。
3. **性能与故障设计**：Redis 只是加速器，不能悄悄变成单点；异步任务必须有容量和丢失边界。
4. **工程证据**：测试、CI、压测原始报告、监控截图和设计说明都能复现。

代码可以由你、Codex 或 Cursor 协作完成，但下面几条核心链路必须能独立讲清：

- 创建短链为什么不会因重试产生重复数据；
- 自动短码和自定义短码如何避免冲突；
- 用户为什么不能修改别人的链接；
- 禁用或更新后，旧缓存为什么不会长期继续跳转；
- 点击统计在哪些故障下可能少记或重复，项目如何处理。

### 0.2 三个版本的范围

| 版本 | 目标 | 必做成果 | 是否适合写简历 |
|------|------|----------|----------------|
| V1 | 正确可用 | 完整链接管理、JWT、`/r/:code` 基础跳转、过期/禁用、自定义短码、幂等、迁移、测试 | 只能说“完成项目”，亮点较少 |
| V2 | 简历级 | Cache Aside、`singleflight`、Redis 降级、原子限流、有界统计、CI、监控、Docker、基础故障演练和一份可复现压测报告 | 达到验收后可以描述已实现能力，但数字只能引用实测结果 |
| V3 | 强化亮点 | Redis Streams + 全局 `event_id` 幂等消费、pprof 优化前后对比、扩展故障演练 | 用于拉开差距；布隆过滤器等仍按证据选做 |

**本章只追求 V1 完整，不急着堆中间件。** V2、V3 在第 11 章完成。

## 1. 产品边界与架构

### 1.1 V1 的边界

V1 是一个 **模块化单体**，不是微服务：

- 一个 API 进程；
- 一个 MySQL，保存权威业务数据；
- 一个 Redis，V1 仅供开发环境和后续 V2 使用；
- 不引入 Kubernetes、gRPC、消息队列等与当前规模无关的复杂度。

```mermaid
flowchart LR
    C["客户端"] --> H["Gin Handler"]
    H --> S["Service 业务规则"]
    S --> R["Repository"]
    R --> M[("MySQL：权威数据")]
    S -. "V2 缓存/限流/统计" .-> D[("Redis：可降级依赖")]
```

**重要原则**：V1 的创建短码不依赖 Redis，因此 Redis 故障不会阻断核心写路径。第 4 节会解释为什么不再把 `Redis INCR` 作为唯一方案。

分层判断规则：

- Handler 只做参数绑定、鉴权上下文读取和响应转换；
- Service 决定幂等、状态流转、权限和事务边界；
- Repository 只封装数据访问，不返回 HTTP 状态码；
- `main` 负责显式组装依赖和优雅关闭，不写业务逻辑。

### 1.3 `main` 骨架：超时配置与优雅关闭

“优雅关闭”不是一句口号，V1 就要写出来。`http.Server` 的四个超时零值都表示“永不超时”，不显式设置时，一个慢客户端（或攻击者）就能长期占住 goroutine 与文件描述符：

```go
// cmd/api/main.go
package main

import (
	"context"
	"errors"
	"log/slog"
	"net/http"
	"os"
	"os/signal"
	"syscall"
	"time"

	"github.com/gin-gonic/gin"
)

func main() {
	// 真实项目在这里加载配置、连接 MySQL/Redis、组装 handler（internal/app）。
	router := newRouter()

	srv := &http.Server{
		Addr:    ":8080",
		Handler: router,
		// 四个超时必须显式设置：零值 = 永不超时。
		ReadHeaderTimeout: 5 * time.Second,  // 读完请求头的上限，防 Slowloris 慢速攻击
		ReadTimeout:       10 * time.Second, // 读完整个请求（含 body）
		WriteTimeout:      10 * time.Second, // 写完响应
		IdleTimeout:       60 * time.Second, // Keep-Alive 空闲连接最长保留时间
	}

	// Ctrl+C（SIGINT）和部署系统发的 SIGTERM 都会取消 ctx。
	ctx, stop := signal.NotifyContext(context.Background(), syscall.SIGINT, syscall.SIGTERM)
	defer stop()

	errCh := make(chan error, 1)
	go func() {
		if err := srv.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
			errCh <- err
		}
	}()

	select {
	case <-ctx.Done():
		slog.Info("shutdown signal received")
	case err := <-errCh:
		slog.Error("http server failed", "err", err)
		os.Exit(1)
	}

	// Shutdown：停止接收新连接，等在途请求处理完；最多等 10 秒。
	shutdownCtx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()
	if err := srv.Shutdown(shutdownCtx); err != nil {
		slog.Error("graceful shutdown failed", "err", err)
	}
	slog.Info("server exited")
}

// newRouter 是占位：真实项目在 internal/app 里注册全部路由（§3.1 有清单）。
func newRouter() *gin.Engine {
	r := gin.New()
	r.Use(gin.Recovery())
	r.GET("/livez", func(c *gin.Context) { c.String(http.StatusOK, "ok") })
	return r
}
```

两个常错点：一是 `Shutdown` 必须传一个**新的**带超时 context，不能复用已被信号取消的 `ctx`（那样会立即超时）；二是 `ListenAndServe` 正常关闭时返回 `http.ErrServerClosed`，要用 `errors.Is` 排除掉，不能当故障处理。V2 引入统计 worker 后，关闭顺序会更讲究（先停入口、再排空队列、最后断开依赖），见第 11 章 §7.3。

`.env.example` 至少包含：

```dotenv
APP_ENV=local
HTTP_ADDR=:8080
MYSQL_DSN=shortlink:dev-password@tcp(127.0.0.1:3306)/shortlink?charset=utf8mb4&parseTime=true&loc=UTC&time_zone=%27%2B00%3A00%27
```

启动时必须校验：生产环境 JWT 密钥不能是默认值；`PUBLIC_BASE_URL` 必须是合法 `http/https` URL；数据库连接超时和连接池上限必须显式配置（具体代码与参考值见 §2.4）。

时间统一规则：API 解析 RFC3339 后转 UTC；Go 内部使用 `time.Now().UTC()`；DSN 使用 `loc=UTC` 并把 MySQL session `time_zone` 设为 `+00:00`；`DATETIME(3)` 一律按 UTC 写入和比较。这样 `NOW()`、`CURRENT_TIMESTAMP`、过期判断、幂等清理和 outbox 重试不会因开发机处于 Asia/Shanghai 而错位。

### 2.2 不把 `AutoMigrate` 当生产迁移

开发早期可以用 `AutoMigrate` 看模型，但正式项目改用 `goose` 或 `golang-migrate`：

- 所有表结构变更都进入 `migrations/`；
- CI 在空数据库执行全部 `up`；
- 已发布迁移不直接改写，错误用新迁移修复；
- 应用启动与迁移命令分开，避免多实例同时改表。

只说纪律不给命令，等于没讲。以 `golang-migrate` 为例，在 PowerShell 里：

```powershell
# 安装 CLI（也可以 scoop install migrate）
go install -tags mysql github.com/golang-migrate/migrate/v4/cmd/migrate@latest

# 生成一对新迁移文件：migrations/000002_add_click_events.up.sql / .down.sql
migrate create -ext sql -dir migrations -seq -digits 6 add_click_events

# 对本地库执行全部 up / 回退一步（连接串与 .env 一致，PowerShell 里整体加引号）
migrate -path migrations -database "mysql://shortlink:dev-password@tcp(127.0.0.1:3306)/shortlink" up
migrate -path migrations -database "mysql://shortlink:dev-password@tcp(127.0.0.1:3306)/shortlink" down 1
```

选 `goose` 的话，等价命令是：

```powershell
go install github.com/pressly/goose/v3/cmd/goose@latest
goose -dir migrations mysql "shortlink:dev-password@tcp(127.0.0.1:3306)/shortlink?parseTime=true" up
```

把常用目标固化进 `Makefile`（Windows 本机可在 Git Bash 里执行 `make`，或 `scoop install make`；CI 的 Linux 环境直接可用）：

```makefile
MYSQL_URL ?= mysql://shortlink:dev-password@tcp(127.0.0.1:3306)/shortlink

.PHONY: migrate-up migrate-down migrate-new test
migrate-up:
	migrate -path migrations -database "$(MYSQL_URL)" up
migrate-down:
	migrate -path migrations -database "$(MYSQL_URL)" down 1
migrate-new:                       # 用法：make migrate-new name=add_click_events
	migrate create -ext sql -dir migrations -seq -digits 6 $(name)
test:
	go test -race ./...
```

### 2.3 V1 完整数据模型

下面是核心迁移示例。状态约定：`1=active`、`2=disabled`。过期不是第三种持久状态，而是由 `expires_at <= NOW()` 计算出的有效状态——不要靠后台任务把过期行改写成“过期状态”：任务可以做清理或统计，但阻止过期链接跳转必须依赖读取时的动态判断，否则任务一旦延迟或漏跑，过期链接就会继续生效。

```sql
CREATE TABLE users (
    id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    username      VARCHAR(32) NOT NULL,
    email         VARCHAR(254) NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    status        TINYINT UNSIGNED NOT NULL DEFAULT 1,
    created_at    DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    updated_at    DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3)
                                  ON UPDATE CURRENT_TIMESTAMP(3),
    PRIMARY KEY (id),
    UNIQUE KEY uk_users_username (username),
    UNIQUE KEY uk_users_email (email)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE short_links (
    id             BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    user_id        BIGINT UNSIGNED NOT NULL,
    short_code     VARCHAR(32) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
    original_url   VARCHAR(2048) NOT NULL,
    url_hash       BINARY(32) NOT NULL,
    status         TINYINT UNSIGNED NOT NULL DEFAULT 1,
    expires_at     DATETIME(3) NULL,
    click_count    BIGINT UNSIGNED NOT NULL DEFAULT 0,
    version        BIGINT UNSIGNED NOT NULL DEFAULT 1,
    created_at     DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    updated_at     DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3)
                                   ON UPDATE CURRENT_TIMESTAMP(3),
    deleted_at     DATETIME(3) NULL,
    PRIMARY KEY (id),
    UNIQUE KEY uk_short_links_code (short_code),
    KEY idx_short_links_user_created (user_id, deleted_at, created_at, id),
    KEY idx_short_links_user_status_created (user_id, deleted_at, status, created_at, id),
    KEY idx_short_links_user_url_hash (user_id, url_hash),
    KEY idx_short_links_expires (expires_at),
    CONSTRAINT fk_short_links_user FOREIGN KEY (user_id) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 只有请求 reuse_existing=true 时才使用这张表。
-- 它指向“当前可复用”的链接，避免把普通创建强制去重。
CREATE TABLE link_dedup_keys (
    user_id     BIGINT UNSIGNED NOT NULL,
    url_hash    BINARY(32) NOT NULL,
    link_id     BIGINT UNSIGNED NULL,
    updated_at  DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3)
                              ON UPDATE CURRENT_TIMESTAMP(3),
    PRIMARY KEY (user_id, url_hash),
    KEY idx_link_dedup_link (link_id),
    CONSTRAINT fk_link_dedup_user FOREIGN KEY (user_id) REFERENCES users(id),
    CONSTRAINT fk_link_dedup_link FOREIGN KEY (link_id) REFERENCES short_links(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 正确性数据放 MySQL，而不是只放可能被淘汰或故障的 Redis。
CREATE TABLE idempotency_records (
    id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    user_id       BIGINT UNSIGNED NOT NULL,
    idem_key      VARCHAR(64) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
    request_hash  BINARY(32) NOT NULL,
    link_id       BIGINT UNSIGNED NULL,
    expires_at    DATETIME(3) NOT NULL,
    created_at    DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    updated_at    DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3)
                                 ON UPDATE CURRENT_TIMESTAMP(3),
    PRIMARY KEY (id),
    UNIQUE KEY uk_idempotency_user_key (user_id, idem_key),
    KEY idx_idempotency_expires (expires_at),
    CONSTRAINT fk_idempotency_user FOREIGN KEY (user_id) REFERENCES users(id),
    CONSTRAINT fk_idempotency_link FOREIGN KEY (link_id) REFERENCES short_links(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

`000001_init.down.sql` 按外键依赖的逆序删除：`idempotency_records` → `link_dedup_keys` → `short_links` → `users`。生产回滚优先使用新的前向修复迁移；`down` 主要用于本地和 CI 验证迁移是否成对可执行。

设计理由：

- `short_code` 使用 `ascii_bin`，因此 `Ab1` 和 `ab1` 是两个不同短码；应用层也必须保持大小写。
- `short_code` 即使软删除也**永不复用**，避免旧二维码或聊天记录后来跳到另一用户的地址。
- 管理接口使用不可猜业务含义的 `id`；公开跳转只使用 `short_code`。管理资源与公开跳转语义分离后，归属校验统一落在 `id + user_id` 上，以后更换短域名或为同一链接增加别名短码，管理接口都不受影响。
- `version` 用于乐观锁，防止两个页面同时更新导致后提交者静默覆盖前者。
- `click_count` 是已落库的累计值；V2 尚未落库的增量需要在统计响应中说明。

### 2.4 GORM 初始化、连接池与持久化模型

先把数据库连进来。注意两点：不开启 `TranslateError`（我们要拿到原始的 `*mysql.MySQLError` 按索引名判错，§7.1）；连接池四个参数必须显式设置，`database/sql` 的默认值是“无上限打开、只保留 2 个空闲连接”，压力一来就会把 MySQL 连接数打满：

```go
// internal/platform/database/mysql.go
package database

import (
	"fmt"
	"time"

	"gorm.io/driver/mysql"
	"gorm.io/gorm"
)

func Open(dsn string) (*gorm.DB, error) {
	db, err := gorm.Open(mysql.Open(dsn), &gorm.Config{
		// 保持 false：开启后 1062 会被翻译成 gorm.ErrDuplicatedKey，
		// 丢失“撞在哪个唯一索引上”的信息，§7.1 的判定就做不了。
		TranslateError: false,
	})
	if err != nil {
		return nil, fmt.Errorf("open mysql: %w", err)
	}

	sqlDB, err := db.DB()
	if err != nil {
		return nil, fmt.Errorf("get sql.DB: %w", err)
	}
	// 参考值按“单实例 + MySQL 默认 max_connections=151”给出，压测后再调（第 11 章 §8）。
	sqlDB.SetMaxOpenConns(25)                  // 上限 = (max_connections - 运维预留) / 实例数
	sqlDB.SetMaxIdleConns(25)                  // 与上限一致，避免高峰期反复建连
	sqlDB.SetConnMaxLifetime(30 * time.Minute) // 定期换连接，配合 LB/防火墙回收空闲 TCP
	sqlDB.SetConnMaxIdleTime(5 * time.Minute)  // 空闲连接提前归还，低峰期不占资源
	return db, nil
}
```

使用规则：

- `gorm.DeletedAt` 的效果：字段零值写入 `NULL`；普通查询自动追加 `deleted_at IS NULL`；`tx.Delete` 变成 `UPDATE ... SET deleted_at = ?`（软删除）；确要查已删数据用 `Unscoped()`。这正好实现 §3.4 “删除不释放短码”的语义。
- 每次数据库调用都写成 `db.WithContext(ctx)`：请求超时或客户端断开时，取消信号能传导到数据库驱动，避免僵尸查询。
- `IdempotencyRecord`、`LinkDedupKey` 没有 `DeletedAt`，它们是控制数据，直接硬删。
- 事务写法与陷阱集中在 §7.2 讲。

### 3.2 创建请求

```http
POST /api/v1/links HTTP/1.1

Idempotency-Key: 84d77273-7de8-4fe7-bf9b-2cad63f5d855
Content-Type: application/json

{
  "original_url": "https://www.example.com/docs?a=1",
  "custom_code": "go-notes",
  "expires_at": "2026-12-31T16:00:00Z",
  "reuse_existing": false
}
```

约束：

- `original_url` 必填，只接受 `http`、`https`，最大 2048 字符；
- `custom_code` 可选，4～32 个 URL 安全字符，需避开保留字；
- `expires_at` 可选，必须晚于当前时间；所有接口使用 UTC/RFC3339，展示层再转时区；
- `Idempotency-Key` 创建时必填，建议 UUID，最大 64 字符；
- `reuse_existing=false` 是默认值，因为同一个长链可能需要不同渠道短码；显式为 `true` 才做用户内业务去重。
- `custom_code` 与 `reuse_existing=true` 不允许同时使用：前者要求创建指定别名，后者要求优先返回已有资源，语义冲突时返回 `400 VALIDATION_ERROR`。

新建返回 `201 Created`；同一幂等请求重放或命中业务去重时返回已有资源和 `200 OK`。只有同一 `Idempotency-Key` 的真实重放才设置：

```http

```

业务去重命中不使用这个响应头，而是在响应 `meta.reuse_reason` 中返回 `business_dedup`，避免把两个概念混为一谈。

### 3.3 列表、详情与状态

```http
GET /api/v1/links?cursor=<opaque>&page_size=20&status=active&keyword=docs
```

- 首次请求省略 `cursor`，后续原样传回响应中的 `next_cursor`；
- `1 <= page_size <= 100`；
- `status` 支持 `active`、`disabled`、`expired`；
- `keyword` 只做必要字段搜索，避免直接拼 SQL；
- 固定排序为 `created_at DESC, id DESC`，保证同一毫秒创建的数据顺序稳定；
- cursor 编码最后一行的 `created_at + id`，SQL 使用同样的复合条件和索引；
- 返回 `items`、`page_size`、`next_cursor`、`has_more`。若页面必须显示总数，单独执行可观测、可限时的 COUNT，不让深分页依赖 OFFSET。

详情和列表中的 `effective_status` 计算顺序：

1. `deleted_at != NULL`：管理查询视为不存在；
2. `status=disabled`：`disabled`；
3. `expires_at <= now`：`expired`；
4. 其他：`active`。

因此列表筛选不能直接写 `WHERE status = 'expired'`：`active` 对应 `status=1 AND (expires_at IS NULL OR expires_at>NOW())`，`expired` 对应 `status=1 AND expires_at<=NOW()`，`disabled` 对应 `status=2`；三者都附带 `deleted_at IS NULL`。

**cursor 的落地**。cursor 就是“上一页最后一行”的排序键，用 base64 编码后交给客户端保管：

```go
// internal/transport/http/handler/cursor.go
package handler

import (
	"encoding/base64"
	"encoding/json"
	"errors"
	"fmt"
	"time"
)

// pageCursor 编码上一页最后一行的 (created_at, id)。
// base64 只是编码不是加密：客户端能看到内容、也可能篡改，
// 所以字段里不放敏感信息，解析失败一律返回 400 VALIDATION_ERROR。
type pageCursor struct {
	CreatedAt time.Time `json:"t"`
	ID        uint64    `json:"i"`
}

func encodeCursor(cur pageCursor) string {
	raw, _ := json.Marshal(cur) // 结构固定，Marshal 不会失败
	return base64.RawURLEncoding.EncodeToString(raw)
}

func decodeCursor(s string) (pageCursor, error) {
	var cur pageCursor
	raw, err := base64.RawURLEncoding.DecodeString(s)
	if err != nil {
		return cur, fmt.Errorf("decode cursor: %w", err)
	}
	if err := json.Unmarshal(raw, &cur); err != nil {
		return cur, fmt.Errorf("unmarshal cursor: %w", err)
	}
	if cur.ID == 0 || cur.CreatedAt.IsZero() {
		return cur, errors.New("cursor missing fields")
	}
	return cur, nil
}
```

翻页 SQL 用“行值比较展开”的写法，过滤与排序都落在 §2.3 的复合索引 `idx_short_links_user_created (user_id, deleted_at, created_at, id)` 上：

```sql
SELECT id, short_code, original_url, status, expires_at, click_count, version, created_at
FROM short_links
WHERE user_id = ? AND deleted_at IS NULL
  AND (created_at < ? OR (created_at = ? AND id < ?))
ORDER BY created_at DESC, id DESC
LIMIT ?;  -- 传 page_size + 1
```

- 多取 1 行：拿到 `page_size + 1` 行说明还有下一页——丢弃最后一行、`has_more=true`，`next_cursor` 编码第 `page_size` 行的 `(created_at, id)`；不足则 `has_more=false`、`next_cursor` 省略。
- 首页（客户端没传 cursor）去掉 `AND (created_at < ? ...)` 这一行即可，其余不变。
- 防篡改：V1 里 SQL 始终带 `user_id = ?`，篡改 cursor 最多让自己翻错页，看不到别人的数据；若仍担心被构造 cursor 探测，可在编码时附加 HMAC 签名（密钥服务端持有），校验失败按非法 cursor 返回 400。

**stats 在 V1 的行为**。`GET /api/v1/links/:id/stats` 返回已落库的累计值，响应结构先定型：

```json
{
  "code": "OK",
  "message": "ok",
  "data": { "click_count": 0 },
  "request_id": "01J2..."
}
```

V1 的 `/r/:code`（§3.7）不做点击采集，`click_count` 通常保持 0；先把路径和字段定下来，是为了 V2 增加统计明细与“未落库增量”口径说明（第 11 章 §4.4）时接口不变。查询同样必须带 `user_id` 归属条件，未命中返回 `404 LINK_NOT_FOUND`。

### 3.4 更新、禁用、启用、删除

更新使用乐观锁：客户端把上次读取到的版本放入 `If-Match`。

```http
PATCH /api/v1/links/123
If-Match: "7"
Content-Type: application/json

{
  "original_url": "https://www.example.com/new-path",
  "expires_at": null
}
```

Go 的更新请求类型必须区分“字段未提供”和“显式传 `null`”。例如清空 `expires_at` 时不能只用普通 `*time.Time` 猜测语义，可使用带 `Set bool` 的 optional wrapper 或 JSON Merge Patch。wrapper 用泛型一次写好：

```go
// internal/transport/http/handler/optional.go
package handler

import "encoding/json"

// Optional 区分“字段未出现”与“显式传 null”。
// encoding/json 只会对出现在 JSON 里的字段调用 UnmarshalJSON，
// 因此 Set=false 一定表示客户端根本没提这个字段。
type Optional[T any] struct {
	Set   bool
	Value T // 字段为 null 时保持零值
}

func (o *Optional[T]) UnmarshalJSON(data []byte) error {
	o.Set = true
	if string(data) == "null" {
		var zero T
		o.Value = zero
		return nil
	}
	return json.Unmarshal(data, &o.Value)
}
```

更新请求直接用它声明字段（`T` 取 `*time.Time` 时，`null` 会落成 `Set=true, Value=nil`）：

```go
type UpdateLinkRequest struct {
	OriginalURL Optional[string]     `json:"original_url"`
	ExpiresAt   Optional[*time.Time] `json:"expires_at"`
}
```

判定规则以 `ExpiresAt` 为例：`Set=false` 不改；`Set=true` 且 `Value=nil` 清空过期时间（改为永不过期）；`Set=true` 且 `Value!=nil` 更新为新时间。注意 `binding` tag 对这种自定义类型无能为力，字段级校验放到 Service 里做。

SQL 更新必须同时限制所有者和版本：

```sql
UPDATE short_links
SET original_url = ?, url_hash = ?, expires_at = ?, version = version + 1
WHERE id = ? AND user_id = ? AND version = ? AND deleted_at IS NULL;
```

- 影响 0 行时，再区分资源不存在和版本冲突；版本冲突返回 `409 VERSION_CONFLICT`。
- `short_code` 创建后不可修改；要换短码就新建链接并禁用旧链接。
- 更新 URL 时，如果 `link_dedup_keys` 正指向该链接，事务应删除旧 hash 指针并尝试登记新 hash；若新 hash 已指向另一条有效链接，则现有指针优先，当前链接仍可用但不成为该 URL 的复用目标。
- 禁用和启用接口自身幂等：已经处于目标状态也返回当前资源。
- 已过期链接不能直接启用，先 PATCH 一个未来的 `expires_at`。
- 删除使用软删除并清理去重指针，但不释放 `short_code` 唯一约束。
- 更新、禁用、启用、删除都必须触发第 11 章的缓存失效流程。

### 3.5 权限规则

Repository 的管理查询直接带上用户条件：

```go
Where("id = ? AND user_id = ? AND deleted_at IS NULL", linkID, userID)
```

不要先按 `id` 查出记录，再在 Handler 临时比较 `user_id`。统一规则是：

- 未登录：`401 UNAUTHORIZED`；
- 已登录但资源不属于他：也返回 `404 LINK_NOT_FOUND`，避免泄露资源是否存在；
- 只有公开跳转接口按 `short_code` 查询，且不返回所有者信息。

至少写一条集成测试：用户 B 对用户 A 的详情、更新、禁用和删除全部得到 404，数据库内容不变。

### 3.6 认证实现要点：bcrypt 密码与 JWT 中间件

users 表的 `password_hash` 列存的是 **bcrypt** 输出，不是加密后的密码——bcrypt 是单向慢哈希，自带随机盐，验证时用 `CompareHashAndPassword` 比对而不是解密。核心取舍在 cost：cost 每加 1 计算耗时翻倍，`bcrypt.DefaultCost`（10）在普通机器上单次约几十毫秒，能同时压住暴力破解收益和登录延迟；机器有余量可以提到 12，但先压测登录接口再改。另一个易踩的坑：bcrypt 只取密码前 72 字节，注册时应把密码长度限制在 8～72 字节。

```go
// internal/service/auth_service.go
package service

import (
	"context"
	"errors"
	"fmt"

	"golang.org/x/crypto/bcrypt"
	"gorm.io/gorm"

	"shortlink/internal/apperror"
	"shortlink/internal/platform/token"
	repo "shortlink/internal/repository/mysql"
)

type AuthService struct {
	db     *gorm.DB
	tokens *token.Manager
}

func NewAuthService(db *gorm.DB, tokens *token.Manager) *AuthService {
	return &AuthService{db: db, tokens: tokens}
}

func (s *AuthService) Register(ctx context.Context, username, email, password string) error {
	if len(password) < 8 || len(password) > 72 { // bcrypt 只取前 72 字节
		return apperror.Validation("password must be 8~72 bytes")
	}
	hash, err := bcrypt.GenerateFromPassword([]byte(password), bcrypt.DefaultCost)
	if err != nil {
		return fmt.Errorf("hash password: %w", err)
	}
	user := repo.User{Username: username, Email: email, PasswordHash: string(hash), Status: 1}
	if err := s.db.WithContext(ctx).Create(&user).Error; err != nil {
		if _, dup := repo.DupIndex(err); dup { // 撞 uk_users_username / uk_users_email（§7.1）
			return apperror.UserConflict()
		}
		return fmt.Errorf("insert user: %w", err)
	}
	return nil
}

func (s *AuthService) Login(ctx context.Context, username, password string) (string, error) {
	var user repo.User
	err := s.db.WithContext(ctx).Where("username = ? AND status = 1", username).Take(&user).Error
	switch {
	case errors.Is(err, gorm.ErrRecordNotFound):
		// 用户不存在也做一次假比较，拉平两个分支的耗时，降低用户名枚举收益
		_ = bcrypt.CompareHashAndPassword(dummyHash, []byte(password))
		return "", apperror.Unauthorized()
	case err != nil:
		return "", fmt.Errorf("load user: %w", err)
	}
	if bcrypt.CompareHashAndPassword([]byte(user.PasswordHash), []byte(password)) != nil {
		return "", apperror.Unauthorized() // 不区分“用户不存在”和“密码错误”
	}
	return s.tokens.Issue(user.ID)
}

// dummyHash 是任意合法的 bcrypt 输出，只用于拉平“用户不存在”分支的响应时间。
var dummyHash = []byte("$2a$10$N9qo8uLOickgx2ZMRZoMyeIjZAgcfl7p92ldGxad68LJZdL17lhWy")
```

防爆破不能只靠 bcrypt 慢：还要限制登录失败次数，例如按 `(username, client_ip)` 计数，15 分钟窗口内失败超过 10 次就暂时拒绝（返回 429，或为不泄露信息仍统一 401）。V1 可以先用一张失败计数表或进程内计数占位，V2 直接复用第 11 章 §3 的 Redis 原子限流实现。

JWT 用 `github.com/golang-jwt/jwt/v5`，算法固定 **HS256**（单服务对称密钥足够；多个服务要独立校验 token 时才考虑 RS256/EdDSA）。claims 只放 `user_id`（放进标准字段 `sub`）与签发/过期时间：payload 只是 Base64 编码，任何拿到 token 的人都能读出来，绝不能放密码、邮箱等敏感数据。过期时间建议 2 小时；V1 过期就重新登录，不做 refresh token——无状态 HS256 token 也无法单个吊销，只能等它过期或全局轮换密钥，这个局限要写进 README。

```go
// internal/platform/token/jwt.go
package token

import (
	"errors"
	"fmt"
	"strconv"
	"time"

	"github.com/golang-jwt/jwt/v5"
)

type Manager struct {
	secret []byte
	ttl    time.Duration
}

// NewManager 强制密钥长度：HS256 的安全性完全取决于密钥强度（§2.1 的启动校验）。
func NewManager(secret string, ttl time.Duration) (*Manager, error) {
	if len(secret) < 32 {
		return nil, errors.New("jwt secret must be at least 32 bytes")
	}
	return &Manager{secret: []byte(secret), ttl: ttl}, nil
}

// Issue 签发 HS256 token，claims 只有 sub（user_id）与时间字段。
func (m *Manager) Issue(userID uint64) (string, error) {
	now := time.Now().UTC()
	claims := jwt.RegisteredClaims{
		Subject:   strconv.FormatUint(userID, 10),
		IssuedAt:  jwt.NewNumericDate(now),
		ExpiresAt: jwt.NewNumericDate(now.Add(m.ttl)),
	}
	return jwt.NewWithClaims(jwt.SigningMethodHS256, claims).SignedString(m.secret)
}

// Parse 校验签名与过期时间，成功则返回 user_id。
func (m *Manager) Parse(tokenStr string) (uint64, error) {
	var claims jwt.RegisteredClaims
	_, err := jwt.ParseWithClaims(tokenStr, &claims,
		func(t *jwt.Token) (interface{}, error) { return m.secret, nil },
		jwt.WithValidMethods([]string{"HS256"}), // 显式限定算法，防算法混淆
		jwt.WithExpirationRequired(),            // 拒绝没有 exp 的 token
	)
	if err != nil {
		return 0, fmt.Errorf("parse token: %w", err)
	}
	uid, err := strconv.ParseUint(claims.Subject, 10, 64)
	if err != nil {
		return 0, fmt.Errorf("invalid subject: %w", err)
	}
	return uid, nil
}
```

校验侧最重要的一行是 `jwt.WithValidMethods([]string{"HS256"})`：不限定算法时，攻击者可以改写 header 里的 `alg` 做算法混淆攻击（历史上有 `alg=none` 绕过签名、把 RS256 公钥当 HS256 密钥两类真实案例）。v5 默认已拒绝 `none`，但显式白名单仍是标准防御，也是面试常问点。

鉴权中间件从 `Authorization: Bearer <token>` 提取并校验，把 `user_id` 写进 `gin.Context`，Handler 通过辅助函数读取。§3.1 的路由片段把它挂在 `/api/v1/links` 分组上：

```go
// internal/transport/http/middleware/auth.go
package middleware

import (
	"strings"

	"github.com/gin-gonic/gin"

	"shortlink/internal/apperror"
	"shortlink/internal/platform/token"
	"shortlink/internal/transport/http/response"
)

const userIDKey = "auth_user_id"

func Auth(tm *token.Manager) gin.HandlerFunc {
	return func(c *gin.Context) {
		tokenStr, ok := strings.CutPrefix(c.GetHeader("Authorization"), "Bearer ")
		if !ok || tokenStr == "" {
			response.WriteError(c, apperror.Unauthorized())
			return
		}
		uid, err := tm.Parse(tokenStr)
		if err != nil {
			// 过期、伪造、算法不符统一 401，不向客户端区分细节
			response.WriteError(c, apperror.Unauthorized())
			return
		}
		c.Set(userIDKey, uid)
		c.Next()
	}
}

// UserID 供 Handler 读取当前登录用户；只在挂了 Auth 的路由里调用。
func UserID(c *gin.Context) uint64 {
	v, _ := c.Get(userIDKey)
	uid, _ := v.(uint64)
	return uid
}
```

Register/Login 的 Handler 只剩参数绑定和响应转换，套用 §8.2 的统一写法即可；登录成功的响应把 token 放进 `data`：`{"code":"OK","data":{"token":"<jwt>","expires_in":7200},...}`。

### 3.7 V1 跳转：纯 MySQL 版 `GET /r/:code`

短链服务的核心用户价值就是“点开能跳”。V1 不做跳转的话，创建出来的短链根本点不开，过期/禁用“不再跳转”的语义也无从验证，所以 V1 就实现一个不带缓存、限流和统计的纯 MySQL 查询版：按 `short_code` 查一次唯一索引 → 校验软删除/状态/过期 → `302` 或 `404`。第 11 章会在这条基线上叠加 Cache Aside（§2）、原子限流（§3）与点击统计（§4），把这里的直查替换成可降级的 Resolver——有 V1 基线，V2 的缓存收益才有对照。

用 302 而不是 301：301 是永久跳转，浏览器和中间代理会长期缓存，链接禁用或改目标后旧客户端可能永远不再回源；302 每次回源，语义正确也便于以后统计。完整对比表见第 11 章 §1.2。

```go
// internal/transport/http/handler/redirect.go
// V1：直查 MySQL；第 11 章 §1.4 会把查询部分替换成带缓存降级的 Resolver。
package handler

import (
	"errors"
	"fmt"
	"net/http"
	"time"

	"github.com/gin-gonic/gin"
	"gorm.io/gorm"

	"shortlink/internal/apperror"
	repo "shortlink/internal/repository/mysql"
	"shortlink/internal/shortcode"
	"shortlink/internal/transport/http/response"
)

type RedirectHandler struct {
	db *gorm.DB
}

func NewRedirectHandler(db *gorm.DB) *RedirectHandler { return &RedirectHandler{db: db} }

func (h *RedirectHandler) Redirect(c *gin.Context) {
	code := c.Param("code")
	if !shortcode.IsValid(code) { // 格式不合法直接 404，不打数据库（§4.2）
		response.WriteError(c, apperror.LinkNotFound())
		return
	}

	var link repo.ShortLink
	err := h.db.WithContext(c.Request.Context()).
		Select("original_url", "status", "expires_at").
		Where("short_code = ?", code). // gorm.DeletedAt 自动追加 deleted_at IS NULL（§2.4）
		Take(&link).Error
	switch {
	case errors.Is(err, gorm.ErrRecordNotFound):
		response.WriteError(c, apperror.LinkNotFound())
		return
	case err != nil:
		response.WriteError(c, apperror.DependencyUnavailable(fmt.Errorf("load link by code: %w", err)))
		return
	}

	// 禁用、已过期与不存在一样返回 404：公开接口只暴露“可跳/不可跳”（§3.5）
	if link.Status != 1 || (link.ExpiresAt != nil && !link.ExpiresAt.After(time.Now().UTC())) {
		response.WriteError(c, apperror.LinkNotFound())
		return
	}

	c.Header("Cache-Control", "no-store")      // 禁止浏览器与中间层缓存这次 302
	c.Header("Referrer-Policy", "no-referrer") // 不把带短码的 Referer 泄露给目标站
	c.Redirect(http.StatusFound, link.OriginalURL)
}
```

每次跳转只走一次 `uk_short_links_code` 唯一索引查询，V1 验收的量级完全够用。服务跑起来后，先创建一条短链，再在 PowerShell 里手动验证：

```powershell
# PowerShell 5.1 的 curl 是 Invoke-WebRequest 的别名，必须写 curl.exe；
# curl.exe 默认不跟随跳转，正好能看到 302 响应本身。
curl.exe -i http://127.0.0.1:8080/r/go-notes
```

第一行应是 `HTTP/1.1 302 Found`，并带 `Location:`、`Cache-Control: no-store` 头；换一个不存在的短码应得到 404 JSON；把这条链接禁用后再访问，应从 302 变成 404——这正是 §0.1 要求“过期/禁用不再跳转”的手工验证方式。

## 4. 短码生成：先理解取舍，再选实现

### 4.1 三种方案

| 方案 | 优点 | 风险/代价 | 本项目定位 |
|------|------|-----------|------------|
| Redis `INCR` → Base62 | 无碰撞、实现直观、码较短 | Redis 成为创建依赖；序列可枚举；故障恢复和多环境序号要设计 | 学习对照方案 |
| DB 自增 ID → Base62 | 不依赖 Redis、无碰撞 | ID 与短码强相关且可枚举；先拿 ID 再更新短码 | 可用但不推荐展示 |
| `crypto/rand` 随机 Base62 + DB 唯一索引重试 | 不依赖 Redis、不连续、较难枚举 | 理论上会碰撞，必须由唯一索引兜底并重试 | **V1 推荐方案** |

`62^8` 是固定的编码空间，不是压测成绩。随机方案仍不能只相信概率，数据库唯一索引才是最终正确性保障。

### 4.2 随机 Base62 示例

下面使用拒绝采样，避免简单 `% 62` 带来的分布偏差：

```go
// internal/shortcode/shortcode.go
package shortcode

import (
	"crypto/rand"
	"fmt"
)

const alphabet = "0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ"
const maxRandomByte = byte(256 - 256%len(alphabet)) // 248

func Generate(length int) (string, error) {
	if length < 6 || length > 32 {
		return "", fmt.Errorf("invalid short code length: %d", length)
	}

	out := make([]byte, 0, length)
	buf := make([]byte, length*2)
	for len(out) < length {
		if _, err := rand.Read(buf); err != nil {
			return "", fmt.Errorf("read crypto random: %w", err)
		}
		for _, b := range buf {
			if b >= maxRandomByte {
				continue
			}
			out = append(out, alphabet[int(b)%len(alphabet)])
			if len(out) == length {
				break
			}
		}
	}
	return string(out), nil
}

// IsValid 校验来自 URL 的短码格式：字母数字开头，其后允许 - 和 _，长度 4~32。
// 与 §4.3 自定义码的正则同一套规则；公开跳转入口（§3.7）也用它先挡掉
// 明显非法的 code，避免无谓的数据库查询。
func IsValid(code string) bool {
	if len(code) < 4 || len(code) > 32 {
		return false
	}
	for i, ch := range code {
		switch {
		case '0' <= ch && ch <= '9', 'a' <= ch && ch <= 'z', 'A' <= ch && ch <= 'Z':
		case (ch == '-' || ch == '_') && i > 0:
		default:
			return false
		}
	}
	return true
}
```

自动码默认 8 位。插入遇到 `uk_short_links_code` 冲突时重新生成，最多重试 5 次；仍失败返回内部错误并记录告警。**不要**先 `SELECT` 判断自动码不存在再插入，因为并发下仍会发生检查后插入竞争。

### 4.3 自定义短码

自定义码先做格式校验，再直接尝试 INSERT，以唯一索引结果为准。不要写成“先 SELECT 判断短码是否被占用、没被占用再插入”：两个并发请求可能同时查到不存在，然后一起插入，前置检查在并发下形同虚设，最终裁决冲突的仍是唯一约束——不如省掉这次查询，直接让 INSERT 的结果说话：

- 建议正则：`^[A-Za-z0-9][A-Za-z0-9_-]{3,31}$`；
- 保留 `api`、`r`、`livez`、`readyz`、`metrics`、`debug`、`admin` 等系统词；
- 冲突返回 `409 SHORT_CODE_CONFLICT`，不自动替用户改名；
- 大小写敏感规则必须在 API 文档中明确；
- 删除后也不能由其他人重新注册同一短码。

### 4.4 如果仍想实现 Counter + Base62

可以把它作为一个可切换的 `CodeGenerator` 实现来学习，但必须把取舍写进 ADR：

```go
type CodeGenerator interface {
	Next(ctx context.Context) (string, error)
}
```

Redis 故障时不要执行危险的 `DECR` 回滚，也不要在多个生成器之间无规则切换。可选策略只有两类：

1. **严格模式**：创建返回 `503 DEPENDENCY_UNAVAILABLE`，等 Redis 恢复；
2. **预先设计的降级模式**：不同生成器使用互不重叠的命名空间，且 DB 唯一索引仍兜底。

为了让 V1 在 Redis 下线时仍能创建，本项目默认采用随机 Base62，而不是临时发生故障才“现场切算法”。

## 5. URL 校验与规范化

### 5.1 校验不等于抓取

短链服务只保存并重定向，不主动请求目标 URL，因此本阶段没有典型服务端 SSRF 请求；但仍要防止危险协议和明显脏数据：

- 只允许 `http`、`https`；
- 必须有合法主机名；拒绝 URL 中的用户名密码；
- 保留 fragment：它不会发送给目标服务器，但会影响浏览器最终定位的页面锚点，擅自删除会改变用户语义；
- 限制总长度；可选地拒绝本机/内网地址，具体取决于产品是否允许内部短链；
- 生产环境还需要恶意域名检测、举报和封禁流程，不能声称仅靠正则就“防钓鱼”。

### 5.2 规范化边界

为了计算 `url_hash`，可以安全地：

- scheme 和 host 转小写；
- 删除默认端口 `:80`/`:443`；
- 空 path 统一为 `/`；
- 保留 fragment，并把它纳入业务去重 hash；`https://a/x#one` 与 `https://a/x#two` 可能是两个不同落点。

不要擅自排序或删除 query 参数，因为有些网站参数顺序、重复参数或跟踪参数有业务含义；过于激进的规范化会把本不相同的 URL 算成同一个 hash，造成错误去重。规范化后的 URL 用 SHA-256 得到 `url_hash`。

## 6. 幂等与业务去重不是一回事

先把两个概念分开：幂等处理的是**同一次请求的重试**——网络断开后客户端重发，不能因此多出一条数据，这是正确性问题，靠 `Idempotency-Key` 实现；业务去重是**产品选择**，决定同一用户再次提交相同目标 URL 时是否复用已有链接，靠 `reuse_existing` 显式开启。两者的触发条件、存储表和失败语义都不同，必须分开实现。

### 6.1 创建幂等

场景：客户端已提交成功，但响应途中断网，于是用相同 `Idempotency-Key` 重试。

事务内流程：

1. 对规范化请求体计算 `request_hash`；
2. 尝试插入 `(user_id, idem_key, request_hash)`；唯一冲突时用 `SELECT ... FOR UPDATE` 按 `(user_id, idem_key)` 锁定读取旧记录；
3. 相同 key、相同 hash 且 `link_id` 已写入：返回原资源；若出现已提交但 `link_id` 为空，视为数据不变量破坏并告警；
4. 相同 key、不同 hash：返回 `409 IDEMPOTENCY_KEY_REUSED`；
5. 首次请求创建短链，将 `link_id` 写回幂等记录后一起提交。

幂等记录建议保留 24 小时并由定时清理任务删除。事务读取到已过期但尚未清理的记录时，应在锁内回收后再创建；清理只影响未来重放窗口，不删除业务链接。

第 2 步必须是**锁定读**（locking read），不能用普通 `SELECT`。InnoDB 默认隔离级别 REPEATABLE READ 下，普通 `SELECT` 是快照读：读的是事务第一次一致性读时建立的快照。如果本事务在 INSERT 之前已经执行过任何普通查询（快照已建立），冲突后的普通 `SELECT` 可能看不到并发事务刚提交的那条幂等记录，出现“INSERT 说它存在、SELECT 说它不存在”的诡异分支。`SELECT ... FOR UPDATE` 是**当前读**（current read）：绕过快照读取最新已提交的版本，并对该行加排他锁——上一段说的“过期记录在锁内回收再创建”也正是靠这把锁避免被并发请求穿插。快照读与当前读的区别是 Go 后端面试里 MySQL 事务的常考点；GORM 里用 `tx.Clauses(clause.Locking{Strength: "UPDATE"})` 生成 `FOR UPDATE`，完整代码见 §7.2。

最后是存储位置：幂等记录必须放在 MySQL，不能图快放进 Redis。Redis 除了可能故障，还会因内存淘汰策略静默丢 key，也可能被运维清空——任何一种都会让“同一 key 的重试”被误判成首次请求而重复创建数据。凡是决定正确性的数据（幂等记录、链接状态），一律以 MySQL 为权威来源，Redis 只做可降级的加速层。

### 6.2 业务去重

同一用户可能故意为同一 URL 建多个码用于渠道统计，所以不能默认全局去重。只有 `reuse_existing=true` 时：

1. 对 `(user_id, url_hash)` 执行 `INSERT ... ON DUPLICATE KEY UPDATE`，确保去重键存在；
2. `SELECT ... FOR UPDATE` 锁住 `link_dedup_keys`；
3. 指向的链接若仍 active、未删除、未过期，则直接返回；
4. 否则创建新链接并更新 `link_id` 指针；
5. 禁用或删除链接时清理指针；过期链接在下一次复用请求中被替换。

第 1 步的完整 SQL 如下。注意 `INSERT ... ON DUPLICATE KEY UPDATE` 语法上必须带至少一个赋值子句，`link_id = link_id` 就是“什么都不改”的合法占位写法，照字面省掉它会得到语法错误：

```sql
INSERT INTO link_dedup_keys (user_id, url_hash, link_id)
VALUES (?, ?, NULL)
ON DUPLICATE KEY UPDATE link_id = link_id;
```

这条语句不论走 INSERT 分支还是 UPDATE 分支，都会让当前事务持有该 `(user_id, url_hash)` 行的排他锁。所以第 2 步的 `SELECT ... FOR UPDATE` 不是“再去抢锁”，而是在已持锁的行上读出当前 `link_id` 指针——锁由第 1 步拿到，读由第 2 步完成，两个并发的 `reuse_existing=true` 请求会在第 1 步就排好队。

`link_id` 允许 NULL，是为了让第一次请求能在创建链接前先插入一行占位并取得该 `(user_id, url_hash)` 的事务锁；提交前必须更新为真实 link id。这样既能并发去重，也不会禁止用户显式创建多个营销短链。

## 7. 创建链路的事务算法

Handler 不应把所有错误都当 400。Service 的主要流程可以按下面实现：

```text
校验 JWT 用户
  → 绑定并校验请求
  → 规范化 URL，计算 url_hash 和 request_hash
  → 开启 MySQL 事务
      → 获取/创建幂等记录
      → 若为重放，读取原链接并返回
      → reuse_existing=true 时锁定去重键并尝试复用
      → 自定义码：直接插入，唯一冲突返回 409
      → 自动码：随机生成并 INSERT，唯一冲突最多重试 5 次
      → 更新去重指针和幂等记录
    提交事务
  → V2 中投递缓存预热/失效事件
  → 返回 201 或 200
```

### 7.1 识别唯一冲突：`errors.As` 与 MySQL 1062

整条链路靠“撞唯一索引”发现并发冲突，所以第一块基础设施是把 GORM 返回的 error 还原成 MySQL 错误，并区分撞了哪个索引。1062 是 MySQL 的重复键错误码，错误消息里带索引名（MySQL 8 形如 `Duplicate entry 'x' for key 'short_links.uk_short_links_code'`）：

```go
// internal/repository/mysql/duperr.go
package mysql

import (
	"errors"
	"strings"

	driver "github.com/go-sql-driver/mysql"
)

// DupIndex 判断 err 是否为唯一键冲突（MySQL 错误码 1062）；
// 是则返回引发冲突的索引名（去掉表名前缀）。
func DupIndex(err error) (index string, isDup bool) {
	var me *driver.MySQLError
	if !errors.As(err, &me) || me.Number != 1062 {
		return "", false
	}
	msg := me.Message // 形如：Duplicate entry 'x' for key 'short_links.uk_short_links_code'
	const marker = "for key '"
	i := strings.LastIndex(msg, marker)
	if i < 0 {
		return "", true // 是 1062 但解析不出索引名，调用方按未知冲突处理
	}
	name := strings.TrimSuffix(msg[i+len(marker):], "'")
	if j := strings.LastIndex(name, "."); j >= 0 {
		name = name[j+1:]
	}
	return name, true
}
```

这就是 §2.4 坚持 `TranslateError: false` 的原因：开启后 GORM 把 1062 统一翻译成 `gorm.ErrDuplicatedKey`，索引名信息丢失，下面的分支就写不出来——同样是冲突，撞 `uk_short_links_code` 该重试或报 409，撞 `uk_idempotency_user_key` 该走幂等重放，混为一谈就是把并发正确性交给运气。

### 7.2 `db.Transaction` 完整实现

把 §4、§5、§6 的设计合成一份可编译的 Service 代码。为减少一层映射，V1 直接复用 §2.4 的持久化模型和 §8.1 的错误构造器：

```go
// internal/service/link_service.go
package service

import (
	"bytes"
	"context"
	"crypto/sha256"
	"errors"
	"fmt"
	"net/url"
	"strings"
	"time"

	"gorm.io/gorm"
	"gorm.io/gorm/clause"

	"shortlink/internal/apperror"
	repo "shortlink/internal/repository/mysql"
	"shortlink/internal/shortcode"
)

type CreateLinkInput struct {
	UserID        uint64
	IdemKey       string
	OriginalURL   string
	CustomCode    string
	ExpiresAt     *time.Time
	ReuseExisting bool
}

type CreateLinkResult struct {
	Link     *repo.ShortLink
	Replayed bool // 同一 Idempotency-Key 重放（§6.1）
	Reused   bool // reuse_existing=true 命中业务去重（§6.2）
}

type LinkService struct {
	db *gorm.DB
}

func NewLinkService(db *gorm.DB) *LinkService { return &LinkService{db: db} }

func (s *LinkService) Create(ctx context.Context, in CreateLinkInput) (*CreateLinkResult, error) {
	// 纯 CPU 工作放在事务外，缩短锁持有时间（见本节末尾的陷阱清单）
	normalized, err := normalizeURL(in.OriginalURL)
	if err != nil {
		return nil, apperror.Validation("invalid original_url")
	}
	urlHash := sha256.Sum256([]byte(normalized))
	requestHash := hashRequest(normalized, in)

	out := &CreateLinkResult{}
	err = s.db.WithContext(ctx).Transaction(func(tx *gorm.DB) error {
		// 1. 幂等占位：撞 uk_idempotency_user_key 说明同 key 来过（§6.1）
		rec := repo.IdempotencyRecord{
			UserID:      in.UserID,
			IdemKey:     in.IdemKey,
			RequestHash: requestHash,
			ExpiresAt:   time.Now().UTC().Add(24 * time.Hour),
		}
		if err := tx.Create(&rec).Error; err != nil {
			if idx, dup := repo.DupIndex(err); dup && idx == "uk_idempotency_user_key" {
				return s.replay(tx, in, requestHash, out)
			}
			return fmt.Errorf("insert idempotency record: %w", err)
		}

		// 2. 可选业务去重（§6.2）
		if in.ReuseExisting {
			hit, err := s.tryReuse(tx, in.UserID, urlHash[:], out)
			if err != nil {
				return err
			}
			if hit {
				return bindLink(tx, rec.ID, out.Link.ID)
			}
		}

		// 3. 创建链接：自动码撞唯一索引时在同一事务内重试
		link, err := s.insertLink(tx, in, normalized, urlHash[:])
		if err != nil {
			return err
		}
		out.Link = link

		// 4. 回写指针，让后续重放与复用都能找到这条链接
		if in.ReuseExisting {
			if err := tx.Model(&repo.LinkDedupKey{}).
				Where("user_id = ? AND url_hash = ?", in.UserID, urlHash[:]).
				Update("link_id", link.ID).Error; err != nil {
				return fmt.Errorf("update dedup pointer: %w", err)
			}
		}
		return bindLink(tx, rec.ID, link.ID)
	})
	if err != nil {
		return nil, err
	}
	return out, nil
}

// replay 处理幂等冲突分支：必须用 FOR UPDATE 当前读（§6.1）。
func (s *LinkService) replay(tx *gorm.DB, in CreateLinkInput, requestHash []byte, out *CreateLinkResult) error {
	var old repo.IdempotencyRecord
	if err := tx.Clauses(clause.Locking{Strength: "UPDATE"}).
		Where("user_id = ? AND idem_key = ?", in.UserID, in.IdemKey).
		Take(&old).Error; err != nil {
		return fmt.Errorf("lock idempotency record: %w", err)
	}
	// 生产版还要处理 old 已过期的回收分支（§6.1）：锁内删除旧记录后按首次请求继续。
	if !bytes.Equal(old.RequestHash, requestHash) {
		return apperror.IdempotencyKeyReused() // 同 key 不同请求体（§6.1 第 4 步）
	}
	if old.LinkID == nil {
		// 记录已提交却没有 link_id：不变量被破坏（§6.1 第 3 步），告警并按内部错误处理
		return apperror.Internal(errors.New("idempotency record committed without link_id"))
	}
	var link repo.ShortLink
	if err := tx.Where("id = ?", *old.LinkID).Take(&link).Error; err != nil {
		return fmt.Errorf("load replayed link: %w", err)
	}
	out.Link, out.Replayed = &link, true
	return nil
}

// tryReuse 实现 §6.2：IODKU 拿到行锁，再在已持锁的行上读指针。
func (s *LinkService) tryReuse(tx *gorm.DB, userID uint64, urlHash []byte, out *CreateLinkResult) (bool, error) {
	if err := tx.Exec(
		`INSERT INTO link_dedup_keys (user_id, url_hash, link_id) VALUES (?, ?, NULL)
		 ON DUPLICATE KEY UPDATE link_id = link_id`,
		userID, urlHash,
	).Error; err != nil {
		return false, fmt.Errorf("upsert dedup key: %w", err)
	}
	var key repo.LinkDedupKey
	if err := tx.Clauses(clause.Locking{Strength: "UPDATE"}).
		Where("user_id = ? AND url_hash = ?", userID, urlHash).
		Take(&key).Error; err != nil {
		return false, fmt.Errorf("lock dedup key: %w", err)
	}
	if key.LinkID == nil {
		return false, nil // 首次登记，走创建
	}
	var link repo.ShortLink // gorm.DeletedAt 自动过滤已软删除的行（§2.4）
	err := tx.Where("id = ? AND status = 1 AND (expires_at IS NULL OR expires_at > ?)",
		*key.LinkID, time.Now().UTC()).Take(&link).Error
	switch {
	case errors.Is(err, gorm.ErrRecordNotFound):
		return false, nil // 指向的链接已删/禁用/过期：创建新链接并在第 4 步更新指针
	case err != nil:
		return false, fmt.Errorf("load reusable link: %w", err)
	}
	out.Link, out.Reused = &link, true
	return true, nil
}

// insertLink 实现 §4：自定义码冲突直接 409；自动码冲突重试最多 5 次。
func (s *LinkService) insertLink(tx *gorm.DB, in CreateLinkInput, normalized string, urlHash []byte) (*repo.ShortLink, error) {
	const maxRetry = 5
	custom := in.CustomCode != ""
	for attempt := 0; ; attempt++ {
		code := in.CustomCode
		if !custom {
			var err error
			if code, err = shortcode.Generate(8); err != nil {
				return nil, fmt.Errorf("generate short code: %w", err)
			}
		}
		link := repo.ShortLink{
			UserID:      in.UserID,
			ShortCode:   code,
			OriginalURL: normalized,
			URLHash:     urlHash,
			Status:      1,
			ExpiresAt:   in.ExpiresAt,
			Version:     1,
		}
		err := tx.Create(&link).Error
		if err == nil {
			return &link, nil
		}
		idx, dup := repo.DupIndex(err)
		if !dup || idx != "uk_short_links_code" {
			return nil, fmt.Errorf("insert short link: %w", err)
		}
		if custom {
			return nil, apperror.ShortCodeConflict() // 不自动替用户换码（§4.3）
		}
		if attempt+1 >= maxRetry {
			return nil, apperror.Internal(fmt.Errorf("short code collision %d times", maxRetry))
		}
	}
}

func bindLink(tx *gorm.DB, recID, linkID uint64) error {
	if err := tx.Model(&repo.IdempotencyRecord{}).
		Where("id = ?", recID).Update("link_id", linkID).Error; err != nil {
		return fmt.Errorf("bind link to idempotency record: %w", err)
	}
	return nil
}

// hashRequest 覆盖所有影响结果的字段：§6.1 第 4 步靠它发现“同 key 不同 body”。
func hashRequest(normalizedURL string, in CreateLinkInput) []byte {
	expires := ""
	if in.ExpiresAt != nil {
		// 不能直接 fmt 指针：打印出来的是内存地址，每次都不同
		expires = in.ExpiresAt.UTC().Format(time.RFC3339Nano)
	}
	sum := sha256.Sum256([]byte(strings.Join(
		[]string{normalizedURL, in.CustomCode, expires, fmt.Sprintf("%t", in.ReuseExisting)}, "|",
	)))
	return sum[:]
}

// normalizeURL 实现 §5.2 的保守规范化：scheme/host 小写、去默认端口、
// 空 path 补 "/"；query 与 fragment 原样保留。
func normalizeURL(raw string) (string, error) {
	if len(raw) > 2048 {
		return "", errors.New("url too long")
	}
	u, err := url.Parse(raw)
	if err != nil {
		return "", err
	}
	u.Scheme = strings.ToLower(u.Scheme)
	if u.Scheme != "http" && u.Scheme != "https" {
		return "", errors.New("scheme must be http or https")
	}
	if u.Host == "" || u.User != nil { // 拒绝空主机与 user:pass@ 形式（§5.1）
		return "", errors.New("invalid host")
	}
	u.Host = strings.ToLower(u.Host)
	if (u.Scheme == "http" && u.Port() == "80") || (u.Scheme == "https" && u.Port() == "443") {
		u.Host = u.Hostname() // 去默认端口
	}
	if u.Path == "" {
		u.Path = "/"
	}
	return u.String(), nil
}
```

事务写法的几个陷阱，比代码本身更常被面试追问：

- `db.Transaction` 的约定：闭包返回非 nil error 整体回滚，返回 nil 才提交。所以任何一步失败都要直接 `return err`，不能吞掉错误继续往下走——半路失败还提交，就是拿一半的数据当成功。
- MySQL 里一条语句失败（如 1062）只回滚该语句本身，事务仍然有效，因此自动码撞唯一索引后**在同一个事务里**重试是安全的；但死锁（错误码 1213）会回滚整个事务，只能在事务外从头重试整个 `Create`。
- 闭包内所有数据库操作必须用 `tx`；误写成外层 `db` 的语句不在事务里、也不持有锁，会静默破坏原子性，这是 GORM 事务最常见的 bug。
- 事务要短：URL 规范化、hash 计算这类纯 CPU 工作放在事务外，事务内只保留必须原子的数据库操作。

### 7.3 需要特别测试的并发情况

- 20 个并发请求使用同一幂等 key，只生成一条链接；
- 同一幂等 key 配不同请求体，只有第一个成功，其余 409；
- 两个用户同时抢同一个自定义码，只有一个成功；
- 同一用户并发 `reuse_existing=true`，只得到一个可复用链接；
- 自定义短码与 `reuse_existing=true` 同时出现时被明确拒绝；
- 随机码发生人为注入的冲突时会重试，而不是返回 400。

### 8.1 应用错误

错误码是接口契约的一部分，集中定义在一个小包里，Service 直接返回构造器的结果：

```go

	HTTPStatus int
	Message    string

		return e.Code + ": " + e.Err.Error()
	}
```

| 业务码 | HTTP | 使用场景 |
|--------|------|----------|
| `VALIDATION_ERROR` | 400 | JSON、URL、分页或过期时间非法 |
| `UNAUTHORIZED` | 401 | Token 缺失、过期或无效 |
| `FORBIDDEN` | 403 | 已认证但账号状态禁止操作；链接越权仍伪装成 404 |
| `LINK_NOT_FOUND` | 404 | 不存在、已删除或不属于当前用户 |
| `USER_CONFLICT` | 409 | 注册时用户名或邮箱已存在 |
| `SHORT_CODE_CONFLICT` | 409 | 自定义短码已占用 |
| `IDEMPOTENCY_KEY_REUSED` | 409 | 同一 key 对应不同请求体 |
| `VERSION_CONFLICT` | 409 | 乐观锁版本落后 |
| `LINK_EXPIRED` | 409 | 对过期链接执行不允许的状态操作 |
| `DEPENDENCY_UNAVAILABLE` | 503 | 必需依赖暂不可用 |
| `INTERNAL_ERROR` | 500 | 未预期错误 |

规则：

- 不能把 SQL、DSN、堆栈或 `err.Error()` 原样暴露给客户端；
- 每个请求生成/透传 `request_id`，错误响应和结构化日志都带上它；
- MySQL 重复键需识别具体索引，再映射成短码冲突或幂等重放，不能一律返回 500；
- `201` 只用于真正新建，DELETE 成功返回 `204` 且无 JSON body。

### 8.2 错误处理与参数绑定的统一转换

Service/Repository 只返回 error（业务错误用 §8.1 的构造器包着），Handler 不手写状态码。error 到响应的转换集中在一个出口：

```go
// internal/transport/http/response/response.go
package response

import (
	"errors"
	"log/slog"
	"net/http"

	"github.com/gin-gonic/gin"

	"shortlink/internal/apperror"
)

type Body struct {
	Code      string `json:"code"`
	Message   string `json:"message"`
	Data      any    `json:"data,omitempty"`
	Meta      any    `json:"meta,omitempty"`
	Details   any    `json:"details,omitempty"`
	RequestID string `json:"request_id"`
}

// OK 写成功响应；meta 传 nil 时按 §3.2 的约定省略。
func OK(c *gin.Context, status int, data, meta any) {
	c.JSON(status, Body{Code: "OK", Message: "ok", Data: data, Meta: meta,
		RequestID: c.GetString("request_id")})
}

// WriteError 是全项目唯一把 error 变成 HTTP 错误响应的出口。
func WriteError(c *gin.Context, err error) {
	var ae *apperror.AppError
	if !errors.As(err, &ae) {
		ae = apperror.Internal(err) // 未包装的错误一律 500，不泄露 err.Error()
	}
	if ae.HTTPStatus >= http.StatusInternalServerError {
		slog.Error("request failed", "code", ae.Code, "err", ae.Err,
			"request_id", c.GetString("request_id"), "path", c.FullPath())
	}
	c.AbortWithStatusJSON(ae.HTTPStatus, Body{
		Code: ae.Code, Message: ae.Message, Details: ae.Details,
		RequestID: c.GetString("request_id"),
	})
}
```

参数绑定失败也走同一出口。`binding` tag 由 Gin 内置的 validator 执行，`ShouldBindJSON` 失败时要区分两种情况：校验失败返回的 `validator.ValidationErrors` 翻译成对用户有意义的字段说明；JSON 语法错误则不回显细节。下面是创建接口的完整 Handler，把 §3.2 的约束和三种成功分支（201/重放 200/去重 200）全部落地：

```go
// internal/transport/http/handler/link_create.go
package handler

import (
	"errors"
	"fmt"
	"net/http"
	"strconv"
	"strings"
	"time"

	"github.com/gin-gonic/gin"
	"github.com/go-playground/validator/v10"

	"shortlink/internal/apperror"
	repo "shortlink/internal/repository/mysql"
	"shortlink/internal/service"
	"shortlink/internal/shortcode"
	"shortlink/internal/transport/http/middleware"
	"shortlink/internal/transport/http/response"
)

type CreateLinkRequest struct {
	OriginalURL   string     `json:"original_url" binding:"required,url,max=2048"`
	CustomCode    string     `json:"custom_code" binding:"omitempty,min=4,max=32"`
	ExpiresAt     *time.Time `json:"expires_at" binding:"omitempty"`
	ReuseExisting bool       `json:"reuse_existing"`
}

// reservedCodes 是 §4.3 的保留字清单：短码大小写敏感（ascii_bin），按原样精确匹配。
// api、r 不足 4 个字符本就过不了格式校验，列出来是为了和文档清单一一对应。
var reservedCodes = map[string]bool{
	"api": true, "r": true, "livez": true, "readyz": true,
	"metrics": true, "debug": true, "admin": true,
}

type LinkHandler struct {
	links   *service.LinkService
	baseURL string // PUBLIC_BASE_URL，如 http://127.0.0.1:8080/r
}

func NewLinkHandler(links *service.LinkService, baseURL string) *LinkHandler {
	return &LinkHandler{links: links, baseURL: baseURL}
}

func (h *LinkHandler) Create(c *gin.Context) {
	var req CreateLinkRequest
	if err := c.ShouldBindJSON(&req); err != nil {
		response.WriteError(c, apperror.Validation(bindErrMessage(err)))
		return
	}
	idemKey := c.GetHeader("Idempotency-Key")
	if idemKey == "" || len(idemKey) > 64 {
		response.WriteError(c, apperror.Validation("Idempotency-Key header is required, max 64 chars"))
		return
	}
	if req.CustomCode != "" && req.ReuseExisting { // §3.2：语义冲突
		response.WriteError(c, apperror.Validation("custom_code and reuse_existing are mutually exclusive"))
		return
	}
	// §4.3：自定义码先做格式校验再尝试 INSERT；字符集与长度规则复用 shortcode.IsValid（§4.2）
	if req.CustomCode != "" && (!shortcode.IsValid(req.CustomCode) || reservedCodes[req.CustomCode]) {
		response.WriteError(c, apperror.Validation("custom_code has invalid format or is reserved"))
		return
	}
	if req.ExpiresAt != nil && !req.ExpiresAt.After(time.Now().UTC()) {
		response.WriteError(c, apperror.Validation("expires_at must be in the future"))
		return
	}

	res, err := h.links.Create(c.Request.Context(), service.CreateLinkInput{
		UserID:        middleware.UserID(c), // §3.6 的鉴权中间件写入
		IdemKey:       idemKey,
		OriginalURL:   req.OriginalURL,
		CustomCode:    req.CustomCode,
		ExpiresAt:     req.ExpiresAt,
		ReuseExisting: req.ReuseExisting,
	})
	if err != nil {
		response.WriteError(c, err)
		return
	}

	switch {
	case res.Replayed: // 幂等重放：响应头标记，无 meta（§3.2）
		c.Header("Idempotency-Replayed", "true")
		response.OK(c, http.StatusOK, h.toLinkDTO(res.Link), nil)
	case res.Reused: // 业务去重命中：meta.reuse_reason（§3.2）
		response.OK(c, http.StatusOK, h.toLinkDTO(res.Link), gin.H{"reuse_reason": "business_dedup"})
	default:
		response.OK(c, http.StatusCreated, h.toLinkDTO(res.Link), nil)
	}
}

// bindErrMessage 把 validator 的字段错误翻译成简短说明；
// JSON 语法错误不回显细节，避免把请求报文内容带进错误消息。
func bindErrMessage(err error) string {
	var ve validator.ValidationErrors
	if errors.As(err, &ve) {
		parts := make([]string, 0, len(ve))
		for _, fe := range ve {
			parts = append(parts, fmt.Sprintf("%s violates %s", fe.Field(), fe.Tag()))
		}
		return "invalid fields: " + strings.Join(parts, "; ")
	}
	return "malformed request body"
}

type linkDTO struct {
	ID          string     `json:"id"`
	ShortCode   string     `json:"short_code"`
	ShortURL    string     `json:"short_url"`
	OriginalURL string     `json:"original_url"`
	Status      string     `json:"status"`
	ExpiresAt   *time.Time `json:"expires_at"`
	Version     uint64     `json:"version"`
	CreatedAt   time.Time  `json:"created_at"`
}

// toLinkDTO 按 §3.2 的响应示例映射：id 转字符串（避免 JS 端 int64 精度丢失）、
// status 输出 effective_status（§3.3 的计算顺序）。
func (h *LinkHandler) toLinkDTO(l *repo.ShortLink) linkDTO {
	status := "active"
	switch {
	case l.Status == 2:
		status = "disabled"
	case l.ExpiresAt != nil && !l.ExpiresAt.After(time.Now().UTC()):
		status = "expired"
	}
	return linkDTO{
		ID:          strconv.FormatUint(l.ID, 10),
		ShortCode:   l.ShortCode,
		ShortURL:    h.baseURL + "/" + l.ShortCode,
		OriginalURL: l.OriginalURL,
		Status:      status,
		ExpiresAt:   l.ExpiresAt,
		Version:     l.Version,
		CreatedAt:   l.CreatedAt,
	}
}
```

### 8.3 `request_id` 与访问日志中间件

规则里说“每个请求生成/透传 `request_id`”，实现是两个小中间件（§3.1 的路由片段把它们挂在最前面，`request_id` 必须先于 `AccessLog` 和业务 Handler 写入）：

```go
// internal/transport/http/middleware/observability.go
package middleware

import (
	"crypto/rand"
	"encoding/hex"
	"log/slog"
	"time"

	"github.com/gin-gonic/gin"
)

const RequestIDKey = "request_id"

// RequestID 优先透传网关/上游生成的 X-Request-Id，没有才自己生成；
// 同时回写响应头，客户端报障时能带上同一个 id。
func RequestID() gin.HandlerFunc {
	return func(c *gin.Context) {
		id := c.GetHeader("X-Request-Id")
		if id == "" || len(id) > 64 {
			id = newRequestID()
		}
		c.Set(RequestIDKey, id)
		c.Header("X-Request-Id", id)
		c.Next()
	}
}

func newRequestID() string {
	var b [16]byte
	if _, err := rand.Read(b[:]); err != nil {
		return "rid-unavailable" // crypto/rand 失败极罕见，但不能让请求 panic
	}
	return hex.EncodeToString(b[:])
}

// AccessLog 每个请求一行结构化日志，字段固定、可被日志系统索引。
func AccessLog(logger *slog.Logger) gin.HandlerFunc {
	return func(c *gin.Context) {
		start := time.Now()
		c.Next()
		logger.Info("http_request",
			"request_id", c.GetString(RequestIDKey),
			"method", c.Request.Method,
			"path", c.FullPath(), // 用路由模板 /api/v1/links/:id 而非真实 URL，避免高基数
			"status", c.Writer.Status(),
			"duration_ms", time.Since(start).Milliseconds(),
			"client_ip", c.ClientIP(),
		)
	}
}
```

`slog` 的初始化放在 `main`（§1.3 的骨架里加两行即可），JSON 输出便于采集：

```go
logger := slog.New(slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{Level: slog.LevelInfo}))
slog.SetDefault(logger) // 之后全局 slog.Info/Error 都输出 JSON
```

访问日志、§8.2 里 `WriteError` 记录的错误日志都带同一个 `request_id`，一次请求的完整轨迹就能在日志系统里串起来。日志分级、采样与 Prometheus 指标在第 11 章 §5 展开。

### 9.2 集成测试样例：Testcontainers 启动 MySQL 与 20 并发幂等

集成测试的骨架是：起一次性 MySQL 容器 → 空库跑迁移 → 组装真实路由 → `httptest` 起服务 → 发真实 HTTP 请求断言。Windows 上需要 Docker Desktop 处于运行状态；没有 Docker 的环境用 `go test -short` 跳过。下面实现 §7.3 清单里最重要的一条：20 个并发请求同一幂等 key，只生成一条链接。

```go
// tests/integration/create_link_test.go
package integration

import (
	"context"
	"encoding/json"
	"errors"
	"net/http"
	"net/http/httptest"
	"strings"
	"sync"
	"testing"
	"time"

	"github.com/golang-migrate/migrate/v4"
	_ "github.com/golang-migrate/migrate/v4/database/mysql"
	_ "github.com/golang-migrate/migrate/v4/source/file"
	tcmysql "github.com/testcontainers/testcontainers-go/modules/mysql"

	"shortlink/internal/app"
	"shortlink/internal/platform/database"
	repo "shortlink/internal/repository/mysql"
)

func TestCreateLink_ConcurrentSameIdempotencyKey(t *testing.T) {
	if testing.Short() {
		t.Skip("integration test requires docker")
	}
	ctx := context.Background()

	// 1. 一次性 MySQL 容器（首次运行要拉镜像，会比较慢）
	container, err := tcmysql.Run(ctx, "mysql:8.4",
		tcmysql.WithDatabase("shortlink"),
		tcmysql.WithUsername("shortlink"),
		tcmysql.WithPassword("test"),
	)
	if err != nil {
		t.Fatalf("start mysql container: %v", err)
	}
	t.Cleanup(func() { _ = container.Terminate(context.Background()) })

	dsn, err := container.ConnectionString(ctx, "charset=utf8mb4", "parseTime=true", "loc=UTC")
	if err != nil {
		t.Fatalf("connection string: %v", err)
	}

	// 2. 空库执行全部迁移——顺带验证了迁移本身（§2.2 的纪律）
	mig, err := migrate.New("file://../../migrations", "mysql://"+dsn)
	if err != nil {
		t.Fatalf("init migrate: %v", err)
	}
	if err := mig.Up(); err != nil && !errors.Is(err, migrate.ErrNoChange) {
		t.Fatalf("migrate up: %v", err)
	}

	// 3. 组装真实路由。app.NewRouter/app.Config 是 internal/app 的组装层（§1.2）：
	//    创建 service、handler、中间件并按 §3.1 注册全部路由。
	db, err := database.Open(dsn) // §2.4
	if err != nil {
		t.Fatalf("open gorm: %v", err)
	}
	cfg := app.Config{
		JWTSecret:     strings.Repeat("s", 32),
		TokenTTL:      time.Hour,
		PublicBaseURL: "http://127.0.0.1:8080/r",
	}
	ts := httptest.NewServer(app.NewRouter(db, cfg))
	t.Cleanup(ts.Close)

	// 4. 注册并登录拿 token
	postJSON(t, ts, "", "/api/v1/auth/register",
		`{"username":"alice","email":"alice@example.com","password":"correct-horse-battery"}`)
	login := postJSON(t, ts, "", "/api/v1/auth/login",
		`{"username":"alice","password":"correct-horse-battery"}`)
	data, _ := login["data"].(map[string]any)
	token, _ := data["token"].(string)
	if token == "" {
		t.Fatal("login returned no token")
	}

	// 5. 20 个并发请求带同一个 Idempotency-Key
	const n = 20
	body := `{"original_url":"https://www.example.com/docs?a=1"}`
	statuses := make([]int, n)
	var wg sync.WaitGroup
	for i := 0; i < n; i++ {
		wg.Add(1)
		go func(i int) {
			defer wg.Done()
			req, err := http.NewRequest(http.MethodPost, ts.URL+"/api/v1/links", strings.NewReader(body))
			if err != nil {
				t.Error(err)
				return
			}
			req.Header.Set("Content-Type", "application/json")
			req.Header.Set("Authorization", "Bearer "+token)
			req.Header.Set("Idempotency-Key", "same-key-for-all-20")
			resp, err := ts.Client().Do(req)
			if err != nil {
				t.Error(err)
				return
			}
			resp.Body.Close()
			statuses[i] = resp.StatusCode
		}(i)
	}
	wg.Wait()

	// 6. 恰好 1 个 201（真正创建），其余 19 个 200（幂等重放）
	created, replayed := 0, 0
	for _, s := range statuses {
		switch s {
		case http.StatusCreated:
			created++
		case http.StatusOK:
			replayed++
		}
	}
	if created != 1 || replayed != n-1 {
		t.Fatalf("want 1x201 + %dx200, got %v", n-1, statuses)
	}

	// 7. 数据库里只有一条链接
	var count int64
	if err := db.Model(&repo.ShortLink{}).Count(&count).Error; err != nil {
		t.Fatalf("count links: %v", err)
	}
	if count != 1 {
		t.Fatalf("want exactly 1 short link, got %d", count)
	}
}

// postJSON 发送 JSON 请求并解析统一响应体；token 为空表示匿名接口。
func postJSON(t *testing.T, ts *httptest.Server, token, path, body string) map[string]any {
	t.Helper()
	req, err := http.NewRequest(http.MethodPost, ts.URL+path, strings.NewReader(body))
	if err != nil {
		t.Fatalf("new request: %v", err)
	}
	req.Header.Set("Content-Type", "application/json")
	if token != "" {
		req.Header.Set("Authorization", "Bearer "+token)
	}
	resp, err := ts.Client().Do(req)
	if err != nil {
		t.Fatalf("do request %s: %v", path, err)
	}
	defer resp.Body.Close()
	if resp.StatusCode >= 400 {
		t.Fatalf("%s returned %d", path, resp.StatusCode)
	}
	out := map[string]any{}
	if err := json.NewDecoder(resp.Body).Decode(&out); err != nil {
		t.Fatalf("decode response of %s: %v", path, err)
	}
	return out
}
```
